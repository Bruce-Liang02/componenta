# Componenta 架构设计文档

## 一、系统定位

Componenta（组件塔）是一套面向复杂 B 端业务场景的**组件化平台**。核心目标：让复杂 B 端系统的演进像搭积木一样可控。

- **组件可插拔**：同一位置（如列表、表单）可注册多种实现，按场景切换
- **主题可切换**：Token（配色/字号）+ 组件变体 + 布局模板 三层一体的主题切换
- **引擎可独立**：流程/表单/权限/AI 等服务引擎独立演进，通过 API 协同
- **部署可演进**：模块化单体起步，按边界逐步拆分为微服务

## 二、整体架构分层

```
┌─────────────────────────────────────────────────────────┐
│  接入层（多端）：Web / APP / 小程序 / 第三方系统            │
├─────────────────────────────────────────────────────────┤
│  BFF / API Gateway（统一认证、路由、限流、协议转换）         │
├─────────────────────────────────────────────────────────┤
│  业务应用层（薄编排，调用下层引擎）                          │
├─────────────────────────────────────────────────────────┤
│  核心引擎层（独立部署/独立服务）                             │
│  ├─ 流程引擎   ├─ 表单引擎   ├─ 权限引擎                   │
│  ├─ 报表/BI引擎 ├─ 规则引擎   └─ AI服务引擎                 │
├─────────────────────────────────────────────────────────┤
│  通用基础层：用户中心、组织、消息、日志、文件、字典            │
├─────────────────────────────────────────────────────────┤
│  数据层：业务库 / 缓存 / 搜索 / 对象存储 / 消息队列          │
└─────────────────────────────────────────────────────────┘
```

## 五、核心机制

### 5.1 Schema 驱动渲染

- 页面由 `PageSchema`（JSON）描述
- `SchemaRenderer` 根据 Schema 从 `ComponentRegistry` 解析组件并渲染
- 支持组件实现替换（`componentImpl` 字段）

### 5.2 组件注册表

- `ComponentRegistry`：管理"组件类型 → 实现变体"的映射
- 全局单例 `globalRegistry`，应用启动时注册所有组件
- 支持 strict 模式（resolve 失败抛错）

### 5.3 主题包（Theme Pack）

一个主题包包含三层配置：

1. **tokens**：Ant Design Design Token 覆盖
2. **componentVariants**：组件类型 → 实现变体的默认映射
3. **layoutTemplate**：默认布局模板

切换主题包 = 一次性替换这三层。

### 5.4 引擎解耦

- 各引擎（流程/表单/权限/AI）独立 Maven/Gradle 模块
- 通过 Spring API 或 MQ 事件通信
- 未来可拆为独立微服务

## 六、部署形态

**模块化单体起步**：所有模块打包为一个可执行 jar，按包边界隔离。
**渐进微服务**：当某个引擎的负载、迭代速度、团队规模达到阈值时，独立拆分部署。

## 七、关键决策（ADR）

- **ADR-001**：pnpm workspace + Turborepo（轻量、学习曲线低）
- **ADR-002**：后端 Gradle Kotlin DSL（构建速度快、类型安全配置）
- **ADR-003**：Schema v0.1 起步，通过 `version` 字段支持后续演进
- **ADR-004**：主题包采用"Token + 组件变体 + 布局模板"三层结构
- **ADR-005**：admin-shell 用 Ant Design Pro Layout 风格
- **ADR-006**：认证用 Sa-Token（轻量、API 友好），未来可平滑升级 OIDC
